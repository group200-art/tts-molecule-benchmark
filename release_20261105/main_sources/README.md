# Main K=20 scientific sources

This component records the implementations behind all **nine methods × two P(6) backbones**, with 3,905 task-inputs and 20 returned positions per configuration. It accompanies the completed main study, not the older K=1 snapshot. The release-level reproduction commands consume saved outcomes; this component supplies the scientific source/configuration lineage.

Run the source integrity check with Python 3.10 or later, without installing model or chemistry packages:

```bash
python verify_sources.py
```

It verifies released hashes, compiles Python source without importing it, parses JSON, verifies all 3,905 fixed four-shot ICL prompts, and checks the 18-configuration inventory. It performs no generation, property prediction, or training.

`SOURCE_MANIFEST.json` records the original repository-relative path, raw SHA256, released SHA256, and every deployment-identifier normalization. The previously verified supplementary scientific snapshot was preferred wherever available; all of its copied original files still matched the current originals. Host paths and scheduler account names have been replaced by explicit placeholders. Historical source hashes inside contracts remain the original hashes; they are not silently rewritten to bless changed files. A filename containing `draft`, or a historical contract saying `pending`, is preserved provenance, not the current completion status.

The exact success kernel, GoT scorer, Vote selector, Reflexion controller/prompts, precision conversion, and main cluster-bootstrap source are listed in [SOURCE_INVENTORY.md](SOURCE_INVENTORY.md). The archive also retains historical variants used by these modules; use `MAIN_CONFIGURATIONS.json` to identify the accepted configurations. In particular, older property-ranked ToT, greedy s1/Reflexion, beam ICL, and N400 voting are not additional main-study methods.

## Reproducing the historical environment

1. Obtain the base models and GeLLMO P6 adapters from the upstream repositories identified in `snapshot/evidence/upstream_model_check.json`. That record gives pinned revisions and the checked weight hashes. Obtain gated Llama weights through their upstream access process. No model or predictor weights are included here.
2. Obtain MuMOInstruct from its upstream dataset and retain the release's fixed ten-task input manifest and IDs. Do not make a new train/test split. Frozen input-specific four-demonstration prompts are included once under `assets/frozen_icl_prompts/`; they retain the original prompt text, demonstration IDs, draw seeds, generation seeds, and prompt hashes. `materialize_icl_prompts.py --destination YOUR_STAGING_DIRECTORY` expands the identical prompt files into the three historical configuration locations without generating anything.
3. Create separate generation, property-prediction, and original-precision environments using the matching `requirements-*.txt` files and Python versions. These files describe direct dependencies recorded in the actual environments, not a tested fresh-install lock. The complete observed distribution lists are in `snapshot/evidence/environment_versions.json`. The original precision environment additionally requires conda RDKit **2020.03.3** and Python **3.6.13**; a modern replacement changes chemical/rounding behavior. Install PyTorch's recorded CUDA build through the appropriate upstream wheel index.
4. Obtain the external ADMET-AI assets, DRD2 classifier, and SAS fragment scores under their upstream terms. Match the original property/configuration hashes before chemical evaluation. `snapshot/data/props/` contains the original calculation code but omits binary predictor assets. Source validity, original round-two comparison values, and full-precision similarity have distinct roles; keep them separate.
5. For an audited historical continuation, stage `snapshot/` with its existing directory hierarchy, restore the matching immutable run caches, read sets, gate receipts, and per-unit configuration assets, and explicitly map `/REPOSITORY_ROOT`, `/MODEL_ROOT`, `/ENVIRONMENT_ROOT`, `/USER_HOME`, and `/WORK_ROOT` to the new installation. `SOURCE_MANIFEST.json` identifies five omitted execution assets: four large historical per-unit/prompt archives and the internal `configs/recovery.json` failed-unit recovery archive. The recovery archive contains operational history, not a scientific configuration; its original remains local. Reconcile path-dependent identity/hash guards in a separately recorded port; retain the original evidence. The per-method entrypoints and frozen scientific parameters are in `MAIN_CONFIGURATIONS.json` and the underlying contracts.

**This is an archival source subset, not a standalone fresh-generation distribution.** Several accepted configurations are continuations that deliberately reuse verified initial candidates, votes, complete trajectories, or earlier seeds. Model weights, predictor assets, all original response caches, and every gate/read-set artifact are not bundled. Downloading models and installing the requirements alone cannot run those historical continuation scripts. Do not bypass a missing cache/hash check or replace it with a new random run and claim reproduction of the saved study. The release's CPU aggregation/candidate-verification workflows are the portable result-reproduction paths.

## Scope and attribution

The main endpoint is strict improvement in every requested property among the first K physical returned positions, with K=1,5,10,20 taken from the same ordered twenty outputs. Mutagenicity decreases; the other objectives increase. Invalid, empty, and duplicate positions remain in place. The additional similarity threshold belongs to the separately labeled supplementary analysis. Internal generation, scoring, and tool use differ by method; K=20 does not imply matched total compute.

The root upstream project license is preserved in `snapshot/LICENSE`. Vendored Graph of Thoughts files retain their own `vendor/LICENSE` in each source tree. The SAS scorer retains its embedded copyright/license notice. MuMOInstruct-derived prompts are data, distributed under the upstream dataset's CC-BY-4.0 terms with attribution in the release's third-party notice. Model and predictor assets retain their upstream licenses/access conditions; the project code license does not relicense them. The recorded upstream metadata was checked on 2026-11-04 and is not a new license grant.
